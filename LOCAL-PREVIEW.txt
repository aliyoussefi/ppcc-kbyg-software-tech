PPCC Know Before You Go - local working version

Run from this folder:
  npm start
Or:
  node server.cjs

Preview:
  http://localhost:4173/#start

Optional alternative port:
  node server.cjs 4174

No npm install or build step is required. The server binds only to 127.0.0.1.
The static site has no backend, form submissions or automatic scraping.
Reload the page after an edit. If you edit server.cjs (for example to serve a new file),
restart the server.

Layout:
The outer page is bounded to the browser's dynamic viewport. The header stays
visible; longer sections, sessions and the footer scroll inside the inset guide
region. That region also supports keyboard scrolling. Tab changes return it to
the top. Desktop and short-screen hero sizing keeps the landing controls visible.

Files:
  index.html   - page structure and placeholder branding
  styles.css   - reference-matched dark visual design, planner, map and banner styles
  data.js      - audience, conference facts, checklist, FAQ and the verified evening events
  sessions.js  - official session facts, topic groups, technology names and editorial efficiency notes
  maps.js      - Level 1 and Level 3 floor-plan geometry and the room-string locator
  exporter.js  - dependency-free PDF writer, day-map PNG composer and .ics builder
  app.js       - tabs, video, checklist, search, agenda store, Start page and evening cards
  planner.js   - On the Ground: interactive floor map, session picker, agenda list, exports
  server.cjs   - localhost-only static preview (explicit file whitelist)

Audience:
The Start page speaks to software and technology companies. The topic filters are
Scout / Autopilot, High-tech peers, Cowork, FinOps / cost & ROI, and Engineering & platform.

To add another session: copy its day, time, room, speakers (in the index's order), format and
level into the facts rows; add its note and technology names (from its own title/abstract);
add its ID and collection date to data.research.addedSessions; then update the card count in
the "How were these sessions selected?" FAQ and the counts below. Room strings are matched to
the floor plan by room number, so a new room name needs no map change.
Official titles, speakers, times, rooms, types and levels are retained in
sessions.js. Summaries, efficiency angles and highlights are editorial, not
measured savings or official recommendations. Keep sourceUrl and collectedAt.
Use null for unpublished dates, times or locations. Sessions without a confirmed
conference date appear in a separate Date unconfirmed column. Never invent them.

Technology named by each session (sessions.js, the "tech" map):
Each card shows "Technology showcased" ("Technology discussed" for roundtables) with the
products the session's own official title or abstract names, most prominent first. The same
list appears in the On the Ground picker, the search box, the PDF/PNG and the .ics file.
  - 48 of the 51 sessions name at least one technology. 8760 (Token Meter exec panel), 8849
    (agent pilots ROI roundtable) and 8881 (testing and evals roundtable) name no product, so
    they have no technology line. Do not fill them in from the organizer's tags.
  - Three sessions (8690, 8765, 8821) name only the generic "Power Platform".
  - Only add a name that the official title or abstract itself uses (checked October 19, 2026
    against the 227 session records on the sessions page; 8758 on October 22, 2026 against its
    own session page). The organizer's separate "products"
    tags are not used: they file Cowork, Scout/Autopilot, Work IQ and similar offerings under
    other products (for example a Cowork session tagged Copilot Studio).
  - Each session keeps the wording of its own text: some say Microsoft Autopilot and one says
    Microsoft Scout. Names are not exhaustive and are not a promise of what will be demonstrated.
  - The sessions page defers some long abstracts as "$NN" references in its page data; the
    text sits in an inline "NN:T<hex length>," row elsewhere in the same data stream.

Agenda builder and floor maps (On the Ground tab):
  - Sessions and evening events share one agenda. "Add to agenda" works on the Start page,
    the Evening Events cards, the 3 Perfect Days cards and the On the Ground picker or map.
  - The map highlights rooms with recommended sessions (teal = highlighted top pick,
    lilac = recommended) and numbers your picks in time order. Level and day tabs follow
    your choices. Items at the same time are shown as alternatives, never as conflicts.
  - Exports: PDF with the numbered floor maps for every day, a PNG of the selected day's
    map(s) with a numbered key, and an .ics calendar file (Pacific times converted to UTC).
  - The agenda is stored in this browser only, under the ppcc-personal-guide-v1 key
    (the same key and shape as before, so earlier picks carry over).
  - Room strings in sessions.js are matched to the plan by room number. Unknown rooms
    are simply not drawn. The Grand Garden Arena is not on the Conference Center plans, so
    it is shown as a labeled callout instead.

Floor plan source / rights:

  room layout in MGM Grand's published Conference Center plans:
  https://assets.contentstack.io/v3/assets/bltc6ce635bc4868eb2/blt502793a96bf24351/mgm-grand-meetings-conference-center-facilities-guide.pdf

Local browser state:
Checklist and agenda IDs use the ppcc-personal-guide-v1 localStorage key.
State is private to this browser origin. No private account data is included.
The page uses network access for Google Fonts and the public YouTube thumbnail;
the player loads only after the user chooses to play the video. Exports are built
in the browser and are never uploaded.

GitHub:
Source: https://github.com/aliyoussefi/ppcc-kbyg-software-tech (public repository, main branch).
Live site: https://aliyoussefi.github.io/ppcc-kbyg-software-tech/ (GitHub Pages, deployed from
the main branch root with no build step; a push goes live in about a minute, and browsers may
cache pages for up to 10 minutes).
The static files index.html, styles.css, data.js, sessions.js, maps.js, exporter.js,
app.js and planner.js run on GitHub Pages without the preview server or any build tooling.
Every path is relative, so they work from the repository subpath.
server.cjs, package.json and this file are only for the local preview, but Pages publishes
every file in the repository root, so never commit private notes or drafts there. A new
script must also be added to the server.cjs whitelist for the local preview.
The git data folder is kept outside OneDrive so sync cannot corrupt the repository; the
".git" file in this folder points to it.
Review branding, dates, source permissions and content before pushing changes, because every
push to main updates the live site.
